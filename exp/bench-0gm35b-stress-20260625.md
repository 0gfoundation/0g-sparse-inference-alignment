# 0GM-35B 极限并发压测（`--stress`）— 2026-06-25

## 背景

本次压测在 OverflowError crash 修复（commit `39d9564`）后进行，目的是验证高并发下服务稳定性，
并获取 SIA vs noSIA 的完整并发扫描基线（conc=1 ~ 432）。

修复内容：`src/sia_vllm_RM.py` 及 `src/sia_rm/client.py` 中对所有接收外部 token ID 的 `decode()`
调用点增加 `try-except (OverflowError, ValueError)` 防护，防止高并发下 vLLM 偶发无效 token ID
导致 EngineCore 崩溃。

已包含的优化（相对于 bench-v2 2026-06-17 基线）：
- **批量打分**（commit `6b6f239`）— VM 串行 N 次调用 → 一次批量调用，conc=16 ITL −33%
- **P-3 增量前缀缓存**（commits `93b732e` + `e87ace1`）— cross-step APC 命中率 100%，conc=16 ITL 再降 −5.7%

### 关键结论

1. **SIA 峰值吞吐 684 tok/s（conc=84）**，相比 bench-v2 基线（239.4，conc=16）提升 +186%，
   主要来自批量打分 + P-3 增量前缀缓存两项优化。

2. **noSIA 峰值吞吐 ~2983 tok/s（conc=288）**，SIA 峰值 / noSIA 峰值 ≈ **23%**。

3. **ITL 倍数在高并发趋于平稳**：conc=16 时 3.1×，conc=128+ 时约 4.3~4.8×；
   相比 bench-v2（conc=16 时 4.8×），批量打分后 ITL 倍数明显改善。

4. **TTFT 随并发急剧上升（SIA 侧）**：conc≥128 时 TTFT 超过 10 秒，
   原因是高并发下 KV cache 压力导致请求排队；noSIA 侧 TTFT 增幅远小于 SIA。

5. **SIA 服务在 conc=432 时零崩溃**，OverflowError 修复有效。
